# Verified management-client integration

`ManagementClient` remains the canonical HTTP client. Its optional third constructor argument and per-call options allow a trusted host to verify and enroll each actual exchange without replacing fetch, subclassing the client, copying the operation catalog or implementing another transport.

## Actual exchanges and authority

`createClientTransport()` opens a fresh loopback HTTP connection for each exchange. `authority.assertCurrent()` guards construction and response publication; asynchronous `beforeConnect`, `beforeSend(socket)` and `afterResponse(socket)` belong to the host. `sent()` runs synchronously immediately before the first potentially effective write. Sent failures invoke `invalidate()` once. Local response-envelope or result-decoder failures revoke that same exchange authority, including a per-call authority, and prevent subsequent authorized sends. Validated remote API errors preserve their domain-error semantics, even when their code is `API_RESPONSE`. These hooks do not constitute native verification by themselves.

`onExchange(exchange, authority)` runs before body traversal or asynchronous network work. `isClientExchangeForTransport(transport, exchange)` checks exact origin; copies and exchanges from another transport fail. It is not an admission ticket, receipt or proof of completion. The host binds the genuine exchange to its own admission owner. `result` may reject early on cancellation; `settled` waits for owned authority work, decoder, upload/download and the socket's actual close. Neither `destroy()`, a timeout nor the caller result refunds physical capacity.

Per-call `authority`, including explicit heartbeat and close options, avoids shared mutable request context. The constructor authority factory receives the path and that call's options, including its signal. `joinPhysical: true` makes JSON calls and registration wait for actual owned tails on success, failure and cancellation; the canonical MCP entry uses it before finishing a handler. Late-registration cleanup retains its original authority even if a close option proposes another. `capacity: { ordinary, control }` on a client counts its exchanges until physical settlement. `createClientTransport({ capacity })` additionally owns a shared capacity across clients using that transport. Runtime enum and both required capacities are checked. Only authenticated heartbeat, own-client detach and explicit own-session detach can use `capacityClass: "control"`; session detach keeps its 16 MiB catalog response bound. The host must prove the exact owned session binding before selecting Control. Ordinary registration and its abandoned-response detach use the original ordinary class. No other operation can borrow a control slot.

## Registration and close

The registration response is validated for actual actor ID, kind, token and lifetime before `onRegistered`. `registration` exposes ID/kind/lifetime without the private token. With `retainSentRegistration`, caller cancellation stops unsent work but keeps a sent response continuation private. `onRegistered` receives `{ publish: false }` when the caller abandoned the registration. Close waits for its physical tail, then sends one own detach using that original authority. The host must keep the original admission ticket and transfer cleanup ownership before making an actor visible. Cancellation of an additional connect waiter stops only its own wait; it does not own or abandon the registration. The finite registration deadline can still leave an unknown effect; this option does not promise remote cleanup.

`close({ authority, capacityClass })` allows a host to keep pre-publication cleanup on its original ordinary ticket even after canonical connect returned. Abandoned registration always retains that original ordinary class. Close denies synchronously and returns the same completion promise on repeated calls. A `timeout` outside 1 to 2147483647 ms or an unknown `capacityClass` rejects with `INVALID_ARGUMENT` before close begins, so a later valid close still detaches. Both strict and best-effort cleanup await every exchange and stream tail before reporting or suppressing any cleanup failure. `strictLifecycle` prevents reconnecting an invalidated/closed client; `strictCleanup` reports unresolved detach rather than claiming success. Failed strict cleanup retains private unresolved state. Defaults retain legacy explicit reconnect and best-effort close. Native/receipt revocation remains irreversible and prevents further authorized sends.

For an initial `connect({ joinPhysical: true })`, owning cancellation remains active after the registration result until physical settlement. The client rechecks cancellation and lifecycle state before returning; abort or close during that wait cannot return a stale success. A retained owner's abort joins its one original-authority detach. Additional waiters keep their independent cancellation semantics.

## Bounded I/O

The transport counts JSON bytes before serialization, rejects accessors/cycles/non-JSON values, rejects compressed/redirected responses, decodes UTF-8 strictly and bounds cumulative chunks before parsing. Ordinary JSON requests are 1 MiB; catalog-flagged operator requests are 16 MiB and vault restore 48 MiB. Ordinary responses are 16 MiB, backup 48 MiB; registration/control/all errors are 16 KiB. Upload/download streams are 100 MiB with backpressure and actual stream-close joins. These are payload bounds, not a total-heap claim. Transfers have no implicit total-duration timeout; an explicit `timeout` or caller signal still stops them. JSON calls retain a 30-second default, registration/heartbeat five seconds, and client detach two seconds.

## Canonical session event connection

`client.watchSession(sessionId, { authority, signal, messageBytes, queuedBytes, queuedMessages })` authenticates with the client's private token without exposing it. It withholds the actual fresh socket from the HTTP agent until `beforeSend` completes, uses the existing WebSocket protocol, disables compression and redirects, validates the initial canonical attachment and binds subsequent events to its exact session and target. Public decoder/proof failures are sanitized. The default event queue is 64 messages / 1 MiB; attachment frames are separately bounded to 16 MiB with a 1 MiB snapshot. One iterator owns consumption; abandoning it closes the stream. The runtime binds WebSocket cleanup to an exact canonical reader lease (`sessions.attachWithCleanup`); a late old-stream close cannot detach a replacement reader, and a failed stream cleanup never falls back to actor-wide detach. Client close joins all owned streams, including outstanding native checks, auth writes and actual socket closure. Only client requests and viewer messages extend a registration; session output sent to a viewer does not. When a registration expires or its client detaches, the runtime closes that client's viewer sockets with code 1008 and leaves the sessions running.

Local `settled` is physical local completion. It is not a remote reader/writer-detach acknowledgement. A native host must retain any unknown sent session binding and obtain its separately authorized canonical own-session detach acknowledgement before refunding that binding. Per-client 128 local streams do not replace a surviving host broker's global 128 active-or-unknown session bindings. There is no stream lifetime timeout after attachment.

## Configurable canonical MCP entry

`@stark-ai/ssh-manager-mcp/stdio` exports `serveManagementStdio({ createClient, beforeCall, admission, input, output })`. The trusted factory owns bootstrap/endpoint discovery. The entry preserves the canonical non-operator tool registry, schemas, annotations and official SDK transport. `beforeCall(operation, context, args)` receives the validated canonical call input before registration or tool sending and can impose target/argument-specific application policy without removing tools or granting operator authority. Both the default call path and a custom `invoke` wait for physical registration completion and require `registration.kind === "agent"`. Cancelled or failed registration cannot reach the invocation. There is no request-count lifetime or ten-minute expiration.

Reusable `admission: { maxRequests: 8, maxMessages: 16 }` works with the unchanged published SDK 2.3.1. The SSH Manager owns whole-handler observation, actual Writable callback/failed-stream cleanup joins and a version-audited SDK completion checkpoint; IDs and credits remain held through cancellation and subscription teardown. These limits, two ordinary calls, finite per-message/rate and queued-output policies apply by default. A supplied custom transport must bound raw input before parsing and resolve sends only after its actual physical work; the public `createManagementStdioTransport()` provides the canonical callback-aware official stdio transport. MCP client/factory ownership is capped at two. All owned clients finish their cleanup attempts before close reports an error; failed cleanup keeps uncertain client ownership charged. The first malformed input frame synchronously stops admission and starts full cleanup. The official SDK decoder remains authoritative, with bounded raw-line validation through its public `deserializeMessage` to detect JSON syntax errors that SDK 2.3.1 otherwise discards. Reporting callbacks cannot interrupt cleanup through synchronous exceptions or unhandled asynchronous rejections. `usage()` exposes counts without request or credential data.

The [completion contract and optional upstream note](mcp-lifecycle.md) describe the audited SDK pin, future upgrade conditions and regression scope. Official SDK PR #3024 is not a prerequisite; no external merge/release is required and no local dependency patch is supplied.

The package-root `createMcpServer(client, options)` enforces that same registered-agent gate for both invocation paths. The shared tool boundary owns registration and role checks; stdio schedules the entire observed tool handler so validation, policy and registration stay within its active-call budget. Natural EOF and explicit close join the same transport finalizer, remove input/output observers and preserve healthy shared stdout.

## Import-safe CLI and executable entries

`@stark-ai/ssh-manager-runtime/cli` exports `runManagementCliOperation` and `supportsScopedManagementCli` with declarations. The operation helper validates canonical arguments and joins physical completion on its default client path. CLI and MCP entries use `import.meta.main`, supported by the existing Node minimum: direct execution starts them; file, stdin, eval, installed-package and portable-bundle imports do not.

The approved [feature specification and finding matrix](specs/verified-client-integration-spec.md) define regression and delivery requirements.
